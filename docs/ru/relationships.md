# Связи

Связи редактируются прямо в форме создания и единой странице записи, общей кнопкой **Сохранить**.
Для 1:1 и N:1 используется одиночный выбор, для 1:N и M:N — множественный.
Связанные записи должны уже существовать.
Значения сразу доступны для изменения при наличии прав. Пользователи с правом только на просмотр
видят ту же страницу с полями и связями только для чтения.

Поддержаны sync/async SQLAlchemy, sync/async SQL reflection, Peewee и Tortoise.
ORM-адаптеры используют родные операции ORM, reflection — ограничения базы данных.
Обычные поля и все переданные связи сохраняются вместе либо полностью откатываются.

```python
from quite_admin import ModelOptions

admin.register(Product, options=ModelOptions(
    relations=("tags",),
    readonly_relations=(),
    record_label="name",
))
```

`relations=None` автоматически обнаруживает связи, `relations=()` скрывает их.
`readonly_relations` показывает выбранные записи без возможности изменения.
Укажите `record_label` у целевой модели, чтобы выбрать подпись в списке. По умолчанию
используются распространённые названия вроде `name` и `title`, затем первичные ключи.
Исключённые поля никогда не используются как подписи.

Обе стороны должны быть зарегистрированы с одним адаптером. Для цели нужны права списка и просмотра.
Изменение обратного внешнего ключа дополнительно требует права редактирования цели
и доступности её FK-полей для записи. Скрытые/read-only поля источника и скрытые FK цели защищены.
Если связь отображается, обычный ввод её внешнего ключа заменяется выбором записи.

Отсутствующая в запросе связь сохраняется. Пустой выбор очищает связь, если FK допускает NULL.
Обязательный FK и delete-orphan нельзя отвязать через этот редактор: связанные записи не удаляются.
Для переноса обязательной дочерней записи выберите другого родителя в её собственной форме.
Неверные ключи, недоступные цели и нарушения ограничений отменяют всё сохранение.

Reflection обнаруживает простые M:N-таблицы с двумя FK и уникальным составным ключом.
Промежуточные таблицы с дополнительными данными требуют адаптера приложения.
Связи 1:1 определяются по первичному ключу, уникальному ограничению или полному уникальному
индексу. Частичный уникальный индекс не гарантирует общую кратность. Отражённые уникальные
ограничения MySQL представлены индексами и тоже учитываются.
SQLAlchemy использует объявленные `relationship()`; view-only и dynamic/write-only доступны только
для чтения. Peewee использует FK, backrefs и `ManyToManyField`, Tortoise — родные связи.

Собственные адаптеры могут реализовать экспортируемый `RelationAdapter`: `relations()`,
постраничный `related()` и атомарный `save_relations()`. Исходный скалярный протокол `Adapter`
не меняется. Метаданные представлены `Relation` и не зависят от шаблонов.

Локальное демо содержит Product–Tag (M:N), Customer–Order (1:N) и Customer–Profile (1:1).

## Поиск и выбор

Нажмите **Выбрать записи**, чтобы открыть поиск. Он использует видимые `search_fields`
целевой коллекции (по умолчанию — видимые строки). Результаты загружаются по 25
в стабильном порядке PK; кнопки «Назад/Далее» доступны для всего набора, включая
записи за прежним пределом 1000 кандидатов. В браузер передаются только ключи
и разрешённые подписи. Выбранные записи сохраняются при поиске и смене страницы;
× убирает запись из выбора. Поддерживаются Tab, Space/Enter и Escape. Поиск не
отправляет форму. Связи и поля сохраняются вместе кнопкой «Сохранить изменения».

В одной связи можно выбрать до 1000 записей. Больший существующий состав доступен
только для чтения, чтобы не потерять часть связей. Без JavaScript обычный селектор
содержит первые 25 кандидатов и текущий выбор; для поиска всех записей нужен JavaScript.
При сетевой ошибке выбор сохраняется и доступна кнопка «Повторить».

Endpoint вариантов при каждом запросе проверяет create/edit исходной коллекции,
list/view целевой, ограничения полей и право edit при изменении обратной связи.
Скрытые поля не участвуют в поиске. Встроенный скрипт загружается с того же origin
с SRI; CSP разрешает только его точный SHA-256 на формах с редактируемыми связями.
Inline-скрипты и произвольные скрипты с того же origin остаются запрещены. Свой
`form.html` может использовать стандартную разметку, `picker_messages` и
`editor.endpoint`; `base.html` автоматически подключает переданные `scripts`.
