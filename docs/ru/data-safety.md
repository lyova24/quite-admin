# Доступ к данным и совместимость

## Границы запросов и идентификаторов

Встроенные адаптеры сверяют поля сортировки и поиска со скалярными метаданными
до построения запроса. Значения передаются параметрами драйвера; `%` и `_` в поиске
означают обычные символы. В браузере сортировка доступна только по видимым полям.
Интерфейс не принимает произвольный SQL, выражения фильтрации или выражения колонок.

`Query.validate(schema)` требует неотрицательный offset, limit от 1 до 10 000,
булево направление сортировки и строку поиска до 4096 символов. Поиск допускает
только известные строковые поля. В UI ограничения строже: 100 записей и 500 символов.

Для get/update/delete нужен полный первичный ключ со всеми частями составного ключа.
Пустые ключи, NULL в ключе, операторы вида `id__gt` и неизвестные поля записи
отклоняются. Изменение первичного ключа не поддерживается. Таблица без PK вызывает
явную ошибку: библиотека не угадывает идентификатор строки.

## Скалярные значения

Формы сохраняют Decimal, UUID, enum, даты и время ISO, JSON и целые числа без
промежуточного преобразования в JavaScript Number. Контрактные тесты проверяют
знаковые 64-битные числа. Ограничения точности, диапазона и часового пояса задаёт БД.
SQLite с NUMERIC affinity может терять точность Decimal; для точных вычислений
используйте NUMERIC/DECIMAL в PostgreSQL или MySQL.

Пустой nullable-контрол преобразуется в `None`; строковое поле NOT NULL допускает
пустую строку. JSON поддерживает объекты, массивы и скаляры, если их допускает адаптер.
NaN и Infinity отклоняются. JSON `null` преобразуется в `None`, а ORM и колонка решают,
будет ли это SQL NULL или JSON null. Отдельного переключателя между ними в форме нет.
Reflection не восстанавливает Python-классы UUID и enum из обычного строкового столбца.

## Транзакции и хуки

Каждая запись выполняется в собственной транзакции с rollback при любом исключении.
Поля и связи сохраняются вместе. Чтение закрывает connection/session без commit
транзакции записи. Engine и pool принадлежат приложению, сессии отдельных операций —
адаптеру. Не передавайте общую request-сессию вместо фабрики сессий.

SQL reflection выполняет defaults, constraints, триггеры и каскады БД, но не Python-хуки
ORM и не проверки приложения. Нативные адаптеры вызывают методы сохранения моделей;
обычные save-хуки и события ORM применяются. Явное удаление записи запускает каскады
ORM и БД. Отвязка связи не удаляет связанную запись; обнаруженная опасная отвязка
с delete-orphan блокируется. Для бизнес-правил и soft delete используйте сервисный адаптер.

Тесты проверяют rollback при ограничениях и ошибках хуков, перечитывание значений
после триггеров, каскады, составные PK/FK и продолжение работы после ошибки.

## Проверки СУБД

| ORM / интеграция | Автоматические проверки | Ограничения |
|---|---|---|
| SQL reflection | Sync/async CRUD, фильтры/проекции, составные PK/FK, запись связей | Физическая схема без Python-хуков; только чистые M:N junction-таблицы |
| SQLAlchemy 2.x | Sync/async CRUD, общий контракт, ORM-хуки, связи | Импортированные модели; dynamic/write-only/view-only связи только для чтения |
| SQLModel | Адаптер и registry SQLAlchemy | Отдельного набора SQLModel-моделей пока нет; проверка SQLAlchemy не равна независимой проверке SQLModel |
| Peewee | CRUD в worker, составные ключи, raw FK, M:N и 1:N/1:1 | Нет async Peewee API; базой владеет приложение |
| Tortoise | Async CRUD, raw FK, UUID, JSON, связи | Инициализация в lifespan; нет контракта составного PK |
| Свои адаптеры | Пример без ORM и структурные проверки протокола | Хранилище, транзакции и optional-возможности проверяет автор приложения |

Интеграционные наборы FastAPI и Litestar проверяют авторизацию, CRUD, связи,
ограничения полей и proxy prefixes. Lockfile определяет проверенный набор
зависимостей, а не все версии из разрешённых диапазонов.

| СУБД | Адаптеры и режимы | Подтверждение |
|---|---|---|
| SQLite | SQL reflection sync/async, SQLAlchemy sync/async, Peewee, Tortoise | Полный набор, CI CPython 3.11–3.15 |
| PostgreSQL 17 | Те же шесть режимов | Локально прошли 280 проверок CRUD, безопасности запросов, связей и типов reflection; отдельный CI job |
| MySQL 8.4 | Те же шесть режимов | Те же 280 проверок прошли локально на 8.4.13; отдельный CI job |

MySQL reflection не различает `BOOLEAN` и обычные колонки `TINYINT(1)`.
Контрактная фикстура явно указывает Boolean через [`column_types`](integration.md);
обычные маленькие целые числа остаются числами.
Peewee 3.19 передаёт PyMySQL 1.2 устаревшие аргументы `db` / `passwd`. Тестовый подкласс
базы передаёт `database` / `password`, не подавляя предупреждений и не изменяя объекты
базы приложения. Запросы и транзакции по-прежнему выполняют Peewee и PyMySQL;
именно эта конфигурация подключения проверена серверной матрицей.

Матрица находится в `.github/workflows/databases.yml` и использует временные базы
сервисов. Для локальной проверки создайте **одноразовую** базу `quite_admin_test`:

```bash
uv sync --locked --group database-check
QUITE_ADMIN_TEST_DATABASE_URL='postgresql://quite_admin:local-test-password@127.0.0.1:55432/quite_admin_test' \
  uv run --group database-check pytest tests/test_adapters.py tests/test_adapter_safety.py tests/test_relations.py tests/test_sql_reflection.py -q
```

Для MySQL нужен URL `mysql://`. Тесты создают и удаляют свои таблицы; запускайте их
последовательно. Fixture отклоняет нелокальные хосты и другие имена БД. Без переменной
окружения используются изолированные SQLite-файлы или память. Наличие workflow
не подтверждает успешный удалённый запуск. Проверка не охватывает каждую допустимую
версию драйвера, ORM и сервера.
