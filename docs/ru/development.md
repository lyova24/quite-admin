# Разработка и совместимость

Зафиксированная версия библиотеки — **0.3.0** (2026-11-01); следующие изменения получат более высокую версию. Изменения относительно 0.1.0 описаны в
`CHANGELOG.md` репозитория. Повышение MINOR учитывает редакторы связей, фильтры
списков, защиту от устаревших форм, схему БД и настройку интерфейса. Обновление версии не публикует релиз.

## Python

Поддерживаются CPython 3.11–3.15. CI запускает полный SQLite-набор тестов для каждой версии без `continue-on-error`.

Локально проверены Python 3.14.7 и 3.15.2. Нет отдельных гарантий для free-threaded сборок и альтернативных реализаций Python.

[Матрица версий зависимостей](dependency-compatibility.md) проверяет поддерживаемые нижние
границы и новое разрешение дополнительно к lockfile. HTTP-тесты используют
`httpx.ASGITransport` и настоящие lifespan-контексты фреймворков в примерах. Это сохраняет
покрытие HTTP и жизненного цикла со Starlette 0.x и 1.x без разных библиотек TestClient.
Pytest считает `DeprecationWarning` ошибкой; предупреждения зависимостей не подавляются.

## Проверка кода

```bash
uv run pytest -q
uv run ruff check src tests examples
uv run ruff format --check src tests examples
uv build
```

Интеграционные тесты проходят CRUD на SQLite для sync/async SQL reflection,
sync/async SQLAlchemy/SQLModel, Tortoise и Peewee под FastAPI и Litestar. Проверяются
CSRF, mass assignment, read-only поля, XSS, права, rollback, шаблоны, host sessions,
составные ключи, proxy prefixes, конкурентные изменения, поиск связей, фильтры
и метаданные схемы с учётом прав.
PostgreSQL/MySQL используют соответствующие драйверы адаптеров, но в этом репозитории
теперь имеют отдельные [контрактные CI jobs](data-safety.md).
Обе СУБД также проверены локальными контрактными запусками.

Это первая рабочая версия библиотеки. Пока нет загрузки файлов, bulk actions, audit log,
row-level permission API. Встроенные формы атомарно обнаруживают устаревшие записи;
свои адаптеры подключают `CheckedAdapter`. См. [настройку](configuration.md).
Свои страницы пока GET-only.
Reflection не восстанавливает логические типы, потерянные в схеме: UUID в SQLite
может оказаться строкой, а enum — обычным VARCHAR. Для сохранения типов используйте
ORM-адаптер. Автообнаружение требует импортированных моделей и не импортирует весь проект.
Поддержка и ограничения редактора связей описаны в разделе [связей](relationships.md).


## Документация Diplodoc

Исходный язык — английский (`docs/en`), перевод — русский (`docs/ru`). Структура страниц и `toc.yaml` совпадает.

Требования: Node.js 24+ и npm 11.5.1+. Из корня репозитория:

```bash
npm ci
npm run docs:build
npm run docs:serve
```

Сборка появляется в `build/docs`. Откройте [localhost:8001](http://localhost:8001/): корневой URL ведёт в английскую версию. Русская версия доступна по `/ru/`. Сборка проверяет состав переводов, ссылки и предупреждения Diplodoc. CI сохраняет HTML как artifact.

После изменения браузерного демо или общих скриптов запускайте `npm run demo:test`.
Команда пересобирает фиктивные данные и проверяет запись связей, конкурентные изменения,
условия фильтров, компоновку схемы, раскрытие промежуточных таблиц и точность контролов форм.

Отдельный workflow `pages` публикует готовый каталог `build/docs` из `master` через GitHub Pages Actions.
В Settings → Pages выберите **GitHub Actions** как источник. Не запускайте Jekyll над корнем
репозитория или исходной папкой `docs`: Liquid воспринимает Jinja-примеры `{% extends %}`
как свои теги. Готовый artifact содержит `.nojekyll` и сохраняет ассеты `_bundle` Diplodoc.


Новые страницы добавляйте в обе языковые папки и оба `toc.yaml`. Меняйте примеры API синхронно. Настройки находятся в `docs/.yfm`, версия CLI закреплена в `package-lock.json`.


## Браузер и установленный пакет

`npm run browser:test` запускает временный локальный стенд и браузерные тесты.
Сначала установите закреплённые браузеры: `npx playwright install --with-deps`.
Стенд использует только вымышленные записи во временной SQLite БД. CI проверяет
Chromium, Firefox и WebKit, сохраняя скриншоты и трассы ошибок.

После `uv build` запустите `uv run python scripts/check_distributions.py`: оба текущих
артефакта установятся в отдельные чистые окружения с проверкой HTTP и ресурсов пакета.
Нужен доступ к registry для зависимостей и инструментов сборки.
