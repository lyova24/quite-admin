# Релизы и политика совместимости

Версия **0.3.0** зафиксирована **2026-11-01**. Следующие изменения войдут в более высокую версию. Изменения находятся
в `CHANGELOG.md` репозитория. Обновление версии не создаёт тег или релиз.

## Правила версий

- PATCH: совместимые исправления ошибок, безопасности и runtime-зависимостей.
- MINOR: новые возможности; до 1.0 также явно описанные несовместимые изменения.
- MAJOR после 1.0: изменение обязательного API, удаление функций или runtime-поддержки.

Для пакета изменений выбирается один максимальный bump. `pyproject.toml`, публичный
`__version__`, `uv.lock`, README, UI и документация меняются вместе. До первого
опубликованного релиза точка отсчёта — предыдущая записанная версия. Каждая задача
имеет отдельный Conventional Commit. Коммит сам по себе пакет не публикует.
Изменение обязательного контракта адаптера также поднимает `ADAPTER_API_VERSION`.

До 1.0 API предварительный. Breaking defaults полей, изменения шаблонов и API должны
содержать миграцию на двух языках и запись в CHANGELOG.md. После 1.0 deprecated API
сохраняется хотя бы один совместимый minor-релиз с объявлением удаления в следующем
major. Поддержка Python/framework/ORM определяется проверенной матрицей, а не только
диапазонами зависимостей.

## Выпуск

1. Завершить раздел changelog датой релиза и описанием миграции.
2. Выполнить тесты, lint, сборку, документацию и аудит зависимостей.
3. Запустить `python scripts/check_release.py`; тег должен совпадать с `v<project.version>`.
4. Только после явного разрешения создать/push тег. Workflow проверит CPython
   3.11–3.15, все ссылки на версию, сборку и метаданные пакета.
5. Будет создан **черновик GitHub release** с разделом changelog этой версии.
6. Maintainer проверяет и публикует черновик. Событие повторно проверяет/собирает тег
   и публикует в PyPI через отдельное окружение `pypi` и Trusted Publishing.

До публикации настройте PyPI trusted publisher для `release.yml` этого репозитория
и GitHub environment `pypi`. Если нужен ручной барьер, включите required reviewers.
У build jobs нет OIDC write permission; оно есть только у publish job без checkout/build.
Основа — [официальная инструкция PyPI](https://docs.pypi.org/trusted-publishers/using-a-publisher/).
Токены и пароли не должны храниться в репозитории.

## Уязвимости зависимостей

`security.yml` запускает `pip-audit` и `npm audit` при push, PR, вручную и еженедельно.
Python проверяется со всеми зафиксированными extras/dev groups. npm показывает все
уровни и завершает job ошибкой при high/critical. Для публичных PR также работает
[GitHub Dependency Review](https://github.com/actions/dependency-review-action).
Ошибки сети/базы advisories не считаются чистым аудитом. Общих исключений advisory нет.
Приватные сообщения об уязвимостях и политика ранних версий описаны в `SECURITY.md`.

Доработка CI/CD от 2026-11-01 для **0.3.1** обновляет Diplodoc и закрепляет
исправленные транзитивные зависимости: decode-uri-component, fast-xml-parser, glob,
minimatch и KaTeX. Свежий npm-аудит сообщает **ноль уязвимостей**; база advisories
меняется, поэтому проверка повторяется в каждом запуске. `scripts/diplodoc.cjs`
адаптирует старых CommonJS-потребителей к исправленным ESM-экспортам markdown-it
и decode-uri-component на Node 24. Обёртка меняет только interop модулей, сохраняет
аудит и поведение parser. Совместимость проверяется строгой сборкой EN/RU.
Удалите overrides, когда upstream сможет напрямую использовать исправленные версии.

## Обязательные проверки и артефакты

`ci.yml` вызывает переиспользуемые workflows тестов, БД, совместимости и безопасности.
Job **CI ready** завершается ошибкой, если любая группа упала, отменена или пропущена.
Сделайте этот check обязательным для `master`; защита ветки настраивается в репозитории.
Релизный workflow запускает тот же полный барьер для коммита тега до создания черновика
и публикации в PyPI. Обычная проверка версии допускает Unreleased; тег требует даты
в changelog.

CI проверяет Chromium, Firefox и WebKit на временной БД с вымышленными данными:
фильтры и поиск связанных ID, задержку поиска, выгрузку CSV/XLSX, inline-тоглы и
конфликты записи, календарь темы, узкую вёрстку и работу без JavaScript. При ошибках
сохраняются скриншоты и трассы. Wheel и sdist устанавливаются каждый в чистое окружение
вне checkout; проверяются импорт, ресурсы пакета, вход FastAPI/Litestar, фильтры и CSV.

WebKit запускается на macOS. В Linux-сборке Playwright текстовые вложения сейчас
отображаются как страница вопреки корректному Content-Disposition
([ошибка upstream](https://github.com/microsoft/playwright/issues/43763)). На macOS
сценарий проверяет реальные скачивания CSV и XLSX без подмены заголовков ответа.

Pages публикуется после успешного push-запуска `ci` для текущего SHA `master`.
Ошибки, устаревшие коммиты и PR-запуски публикацию не запускают. Ручной запуск
ограничен текущим коммитом `master`.
