# Интерактивная схема базы данных

Откройте **Схема БД** в навигации (`/admin/schema` с учётом вашего mount-префикса).
В схему входят все зарегистрированные коллекции с правами `list` и `view`. По умолчанию
выбраны все эти таблицы, в том числе без связей. Схема строится по метаданным адаптеров:
открытие и перестановка таблиц не читает и не изменяет значения записей.

## Работа со схемой

- **Таблицы** открывает боковую панель. Ищите по названию коллекции или таблицы,
  выбирайте видимые таблицы флажками или кнопками **Показать все** / **Скрыть все**.
  Поиск сокращает список в панели, не меняя схему. Нажатие на название центрирует таблицу.
- В свёрнутой карточке видны первичные ключи и поля связей. Нажмите карточку или
  Enter/Пробел на ней, чтобы увидеть остальные доступные поля; повторное нажатие сворачивает её.
- Линии соединяют участвующие поля. Подписи и окончания различают **1:1 · o2o**,
  **1:N · o2m** и **N:M · m2m**. Выбор таблицы подсвечивает её связи.
- Нажмите подпись **N:M**, чтобы показать промежуточную таблицу и две связи **1:N**.
  Кнопка сворачивания на любой из этих линий возвращает логическую связь M:N.
  Зарегистрированная промежуточная таблица использует существующую карточку;
  незарегистрированная появляется в боковой панели после раскрытия связи.
- Перетаскивайте карточки для перестановки, пустое место — для перемещения схемы.
  Колесо прокручивает схему; Ctrl/⌘ + колесо и кнопки +/− меняют масштаб.
  **Вся схема** показывает все выбранные таблицы; **Автокомпоновка** также сбрасывает
  ручные позиции. Перемещение любой таблицы фиксирует позиции всех видимых таблиц до
  следующей **Автокомпоновки**. Автоматическая компоновка учитывает раскрытые карточки
  и отдельные группы таблиц.
- **Развернуть схему** использует доступное место окна; Escape возвращает обычный вид.
  На узком экране панель таблиц изначально свёрнута. **Открыть коллекцию** ведёт к списку
  записей выбранной зарегистрированной таблицы.

С клавиатуры стрелки перемещают выбранную карточку (Shift увеличивает шаг),
Enter/Пробел раскрывают поля и промежуточные таблицы. При фокусе на полотне +/− меняют
масштаб, 0 вмещает схему. Выбор, раскрытие и позиции сохраняются до ухода со страницы;
после перезагрузки снова выбраны все доступные зарегистрированные таблицы.

## Права и видимость полей

Нужны авторизация и оба права `list` и `view` на каждую коллекцию. Связи с недоступными
коллекциями и через скрытые поля соединения не показываются. Видимость полей определяется
`ModelOptions`, включая стандартное скрытие полей с учётными данными. Зарегистрированная
промежуточная таблица с ограниченными правами не появляется повторно как техническая карточка.

Незарегистрированная промежуточная таблица показывает только метаданные полей от адаптера,
без полей учётных данных. У неё нет перехода к записям и CRUD. Зарегистрируйте и настройте
её как коллекцию, если нужны дополнительные ограничения видимости полей приложения.

Схема использует общие токены темы — см. [кастомизацию интерфейса](styling.md).
Встроенный JavaScript разрешён точным SHA-256 CSP-хешем и SRI только на этой странице.
Политика скриптов собственных страниц не меняется.

## Собственные адаптеры

Для обычных линий достаточно существующего `RelationAdapter.relations()`.
Необязательные `Relation.source_key_fields` и `target_key_fields` описывают реальные
поля соединения, в том числе альтернативные уникальные ключи. `through` называет
промежуточную таблицу M:N, `junction` задаёт её поля и внешние ключи обеих сторон:

```python
from quite_admin import Field, Junction, Relation

Relation(
    name="tags", target=Tag, kind="many_to_many",
    source_key_fields=("id",), target_key_fields=("id",), through="product_tags",
    junction=Junction(
        name="product_tags",
        fields=(
            Field("product_id", int, primary_key=True),
            Field("tag_id", int, primary_key=True),
        ),
        source_fields=("product_id",), target_fields=("tag_id",),
        model=ProductTag,  # необязательно: зарегистрированная модель промежуточной таблицы
    ),
)
```

Метаданные промежуточной таблицы не требуют первичного ключа. Необязательный sync/async
`schema_relations(model)` может отдавать сведения только для схемы, не меняя редактируемые
связи. Встроенный адаптер SQLAlchemy также показывает физические FK без ORM `relationship()`.
Версия API адаптера остаётся 1.
